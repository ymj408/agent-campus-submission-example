## 2. 最难的问题

### 2.1 冲突不能被模型“说服”

如果只是提示词写“冲突时不要选一个值”，模型仍可能回答“15 天”。最终把冲突做成运行时事实：

- 读取 D01/D02 后，结构化 facts 同 key 不同 value；
- `conflicts()` 不依赖模型自报；
- 只要检测到冲突，最终 status 强制 `needs_confirmation`；
- 模型 finish 的 answer 只进入 `model_claim`，不进入最终 answer。

测试 `test_runtime_overrides_conflict_lie` 专门让模型谎报 15 天。

### 2.2 引用不能只靠格式

模型可以编造“D02 说 15 天”，也可以引用不存在的原文。最终 citations 从 `read_document` 的 `sections` 重建：

- 每条 canonical citation 都用 `validate_citation` 做精确子串校验；
- 模型 citations 单独校验并记录；
- 错误引用不能污染最终回答。

测试 `test_runtime_rebuilds_invalid_citation` 使用伪 quote，最终回答仍只引用 D01 S2。

### 2.3 范围过滤与检索召回

第一版检索“总部差旅报销”把 D04退款、D05密码也带进来，因为“期限/多久”是共用词。解决：

- 范围词命中时，候选限制在范围文档 + 全国制度；
- 只保留最高分附近（`best - 1`）的候选；
- 这样“总部年假”仍能命中全国 D03，而“总部报销”不会读退款制度。

这是检索工程里典型的 precision/recall 取舍。

### 2.4 冲突发现时机

最初读完全部候选才检查冲突，导致 02 场景多读 3 份无关文档。改为每读一份就检查 `conflicts`：

```text
read D01 → no conflict
read D02 → conflict
→ request_clarification
→ stop
```

既减少调用，也让 Trace 更像真实 Agent。

### 2.5 资料外问题的“诚实”

没有候选时，模型仍可能用常识回答“食堂一般…”。运行时在无候选/无证据时直接 `insufficient_evidence`，answer=null。资料外不是“检索得分低”，而是**没有可引用证据**。

### 2.6 上下文改写

“那总部呢？”如果不改写，检索会沿用上一轮“华南”的语义，答 15 天。Mock 通过范围替换得到“总部 差旅报销期限多久”；真实模型则从 messages 中看到历史。最终输出 `rewritten_query` 和 `history_used`，让改写可审计。

## 3. 学习收获

1. **RAG 的核心不是“搜到”，而是“引用能支持答案”。** 摘要和标题只能用于召回，不能用于回答。
2. **冲突处理必须是独立事实层。** 只靠提示词无法保证不选一个值。
3. **检索需要负样本意识。** “期限/多久”这类高频词会把无关制度带进来，范围+阈值是必要约束。
4. **版本/状态是检索的一部分。** superseded 文档不参与，否则会制造伪冲突。
5. **上下文改写要可观察。** 输出改写后的 query，才能解释为什么这一轮答 30 而不是 15。
6. **资料外要敢于不答。** 无证据时 answer=null 比“看起来合理”更有价值。
